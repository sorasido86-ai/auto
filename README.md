# WordPress 자동 콘텐츠 작업

레시피, 뉴스 키워드, 쇼핑 검색 결과, 동물 사진, 시장 지표를 예약 수집해 WordPress에 게시합니다.

## 2026-10-02 개선 내용

- 레시피는 실제 원문 재료와 조리 순서를 입력으로 사용합니다. 한국어 번역의 재료 수, 단계 수, 수량·시간·온도 숫자를 검사하고, 실패하면 한 번 보정한 뒤 게시를 중단합니다.
- 세 레시피 작업은 원문의 특징에 맞춰 도입과 문단을 편집합니다. 재료 조합·준비 과정·투입 순서·마무리 중 실제 설명 가치가 있는 지점을 선택하고, 필요한 경우에만 원문 단계 번호에 근거한 짧은 설명 문단을 추가합니다. 조리 순서와 계량은 유지합니다.
- 도입·설명은 짧은 문장과 문단으로 나누고 상투적인 예고·과장·가짜 경험담을 차단합니다. 최근 발행한 6개 글의 도입·설명·소제목을 생성 입력으로 제공하며, 같은 문장 재사용과 높은 문자 유사도를 검사합니다. 이름만 바꾼 반복도 보정 대상입니다. 의미상 반복을 모두 검출하는 검사는 아니므로 미리보기로 확인합니다.
- 편집 이력은 게시 성공 후에만 작업별 SQLite에 저장하며 최근 30개를 보존합니다. 미리보기와 게시 실패는 이력에 넣지 않습니다. 캐시가 없으면 이전 글과 비교할 수 없습니다.
- 한식 작업도 기존 OPENAI_API_KEY를 사용하며 OPENAI_MODEL이 비어 있으면 gpt-4.1-mini를 사용합니다. API 키가 없으면 도입을 만들지 않고 원문 재료·단계만 표시합니다. 키가 있는데 생성·검증이 실패한 경우 게시를 중단합니다.
- 제목은 메뉴와 실제 내용 중심으로 작성합니다. 레시피 사진은 해당 원문의 이미지를 사용합니다.
- WordPress 응답이 HTML이거나 타임아웃일 때 생성 요청을 반복하지 않습니다. 고정 slug로 생성 여부를 조회해 복구합니다. 글 조회 실패를 '글 없음'으로 취급하지 않습니다.
- 뉴스의 중복 제목·링크를 제외하고 날짜 없는 헤드라인을 최신 기사로 간주하지 않습니다. 전날 자료가 없으면 증감 수치를 만들지 않습니다.
- 쇼핑 검색 결과는 검색 순서로 표현합니다. 판매량·품질 순위나 개인화 추천으로 표현하지 않습니다. 의류 개수는 실제 수집 건수를 표시합니다.
- 네이버 관심도 비교는 요청마다 공통 기준 키워드를 포함해 지수 크기를 보정합니다. 기준 키워드 자료나 비교 날짜가 없으면 해당 비교를 생략합니다. 후보군 내 비교이며 네이버 전체 검색어 순위가 아닙니다.
- 빈 수집 결과는 게시하지 않습니다. 동물 이미지의 GIF/사진 분류를 실제 수집 그룹 기준으로 수정했습니다.
- 모바일에서 긴 표는 가로로 스크롤합니다. 시장 리포트 CSS는 본문 영역에만 적용합니다.
- 모든 작업에 실행 시간 제한, 동시 실행 제어, 게시 전 회귀 테스트와 HTML 미리보기 저장을 추가했습니다. SQLite 캐시 키는 실행마다 갱신되고 작업별 파일을 독립적으로 복원합니다.

## 확인 방법

GitHub의 **Actions → 원하는 작업 → Run workflow**에서 `dry_run=1`을 선택하면 게시와 이미지 업로드 없이 미리보기만 생성합니다. 결과는 실행 화면 아래 **Artifacts → content-preview-…**에서 내려받을 수 있습니다. AI 레시피의 미리보기 생성에는 기존 OpenAI API 사용량이 발생합니다.

수동 실행의 기본값은 `dry_run=1`입니다. `dry_run=0`은 기존 설정에 따라 게시합니다. 예약 실행은 기존 게시 모드와 시간·카테고리를 유지합니다. 같은 날짜·슬롯의 레시피가 이미 있으면 건너뜁니다. 서로 다른 레시피 작업은 각자의 글 하나를 유지합니다.

SQLite 캐시는 중복 회피와 과거 비교에 사용합니다. 캐시가 삭제돼도 서버의 slug 조회로 같은 날짜의 중복 생성은 막지만 장기 이력 비교에는 과거 자료가 필요합니다. 기존 저장소 DB는 초기 이력으로 유지합니다.

## 검사

```bash
python -m pip install -r requirements.txt
python -m compileall -q .
python -m unittest discover -s tests -v
```

`Quality checks`가 Python 3.11과 3.12에서 독립적으로 검사합니다. 테스트는 외부 API와 WordPress 요청을 모의하며 실제 글을 발행하지 않습니다.

## 검증 범위와 남은 확인

최근 한식·네이버 스타일 작업 로그에서 WordPress 게시 응답의 JSON 해석 실패가 확인됐습니다. 코드에서 오류 진단과 중복 생성 복구를 개선했지만, 서버가 HTML을 반환하는 원인이 REST 차단·리디렉션·보안 플러그인 중 무엇인지는 로그만으로 확정할 수 없습니다. 서버 설정 자체는 이 저장소 변경으로 수정되지 않습니다. 실제 게시 성공 여부는 이후 실행 결과로 확인해야 합니다.

숫자·항목 수 검사는 오역과 사실 오류의 일부를 잡습니다. 식재료명과 문장의 의미를 완전히 검증하는 것은 아니므로 미리보기로 문장 품질을 확인할 수 있습니다. AI 호출이나 수집 실패 때 검증되지 않은 내용으로 대체해 발행하지 않습니다.

공식 데이터 정의: [네이버 쇼핑 검색 API](https://developers.naver.com/docs/serviceapi/search/shopping/shopping.md), [네이버 DataLab](https://developers.naver.com/docs/serviceapi/datalab/search/search.md), [WordPress Posts API](https://developer.wordpress.org/rest-api/reference/posts/).

## 2026-10-05 게시 중단 복구

- AI 출력에 원문 항목마다 필수 번호 필드를 지정하는 구조화 응답을 적용합니다. 필드의 개수를 응답 형식에서 고정하며, 수량·단계·문장 품질 검사는 유지합니다. 글자 수량(two 등)을 같은 값의 숫자로 옮기거나 ½를 1/2로 옮기는 정당한 번역은 허용합니다. 보정 요청에는 실제 이전 응답과 오류 항목 번호·기대 숫자를 전달합니다. STEP 번호 전용 줄을 조리 단계로 세지 않습니다.
- WordPress GET이 HTML 또는 404를 반환하면 공식 `?rest_route=/wp/v2/posts` 경로로 한 번 확인합니다. 유효한 목록을 받았을 때만 해당 경로를 게시에 사용합니다. 두 경로 모두 실패하면 게시를 중단합니다. POST는 경로를 바꿔 재전송하지 않고 slug 조회로만 결과를 복구합니다.
- 세 레시피 작업은 main의 해당 코드·공통 모듈·의존성·워크플로 변경 시에도 실행됩니다. 적용 직후 게시 연결을 검증하며, 같은 날짜의 글은 기존 slug 조회로 중복을 막습니다. 예약 실행 설정은 유지합니다.
- 생성 검증이 계속 실패하면 원문과 마지막 응답·오류를 JSON 진단 자료로 보관합니다. 미검증 내용은 발행하지 않습니다. 실행 Artifacts에는 HTML 미리보기 또는 JSON 진단 자료가 포함될 수 있습니다.
